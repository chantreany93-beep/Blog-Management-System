# Blog Management System

A simple Laravel application for creating and managing blog posts. This educational project demonstrates Laravel MVC, Eloquent CRUD, MySQL migrations, Blade views, Docker Compose, and Git workflows.

## Features

- Create, view, edit, and delete blog posts
- Generate a unique slug automatically from each title
- Save author, content, and Draft/Published status
- Search posts by title and filter by status
- Paginate the post list
- Validate submitted forms and display success/error messages
- Confirm before deleting a post
- Run the Laravel application and MySQL in separate Docker containers

## Technologies

- PHP 8.3
- Laravel 13
- MySQL 8.4
- Blade templates and Bootstrap 5
- Docker and Docker Compose
- PHPUnit

## Requirements

- Docker Desktop with Docker Compose
- Git
- A web browser
- Internet access when building Docker images and loading Bootstrap from its CDN

Composer and PHP are needed on the host only for local development and running the test suite. Docker builds the PHP application image with its required extensions.

## Installation

Clone the repository and enter the project folder:

```powershell
git clone https://github.com/<your-username>/<your-repository>.git
Set-Location .\<your-repository>
```

Create a local environment file, install Composer dependencies, and generate the Laravel application key:

```powershell
Copy-Item .env.example .env
composer install
php artisan key:generate
```

If `.env` already exists, do not overwrite it. Keep `.env` on your computer and never commit it.

## Environment Configuration

Edit `.env` locally before starting Docker:

- Keep `APP_KEY` generated by `php artisan key:generate`.
- Set a strong, unique value for `DB_PASSWORD`.
- Set a separate strong value for `MYSQL_ROOT_PASSWORD`.
- The default database name and application user are `blog_management` and `blog_user`.
- Inside Docker, `DB_HOST=mysql` points to the MySQL service.

The `.env.example` file contains placeholders only. `.env`, passwords, and application keys are excluded from Git and from the Docker build context. Do not put credentials in the Dockerfile or `compose.yaml`.

## Docker Setup

Validate the Compose configuration without displaying its environment values:

```powershell
docker compose config --quiet
```

Build the application image and start Laravel and MySQL:

```powershell
docker compose up --build -d
docker compose ps
```

Run database migrations inside the application container:

```powershell
docker compose exec app php artisan migrate --force
docker compose exec app php artisan migrate:status
```

Open [http://localhost:8000](http://localhost:8000). The MySQL port is available only to the Docker network; application data is persisted in the `mysql_data` volume.

Useful Docker commands:

```powershell
docker compose logs -f app mysql
docker compose stop
docker compose start
docker compose down
```

`docker compose down` stops and removes containers but keeps the database volume. Do not use `docker compose down -v` unless you intend to permanently delete the database data.

## Database Migration

Migrations create the Laravel support tables and the `posts` table. After the containers are running, apply any new migrations with:

```powershell
docker compose exec app php artisan migrate --force
```

For local development with Composer installed, run the automated tests with:

```powershell
php artisan test
```

The feature tests use an in-memory SQLite database and do not modify the MySQL volume.

## CRUD Testing

1. Open [http://localhost:8000](http://localhost:8000) and select **Create Post**.
2. Enter a title, content, author, and status; submit the form. Confirm the detail page shows a generated slug.
3. Create another post with the same title and confirm its slug is unique.
4. Edit a post and confirm the slug updates when its title changes.
5. Search for part of a title and filter by Draft or Published.
6. Add more than 10 posts to check pagination.
7. Select **Delete** and confirm the browser prompt; verify the post is removed.
8. Submit an empty form to see validation errors.

Run the automated feature tests with `php artisan test`; they cover CRUD, slug generation, validation, search/filter, and pagination.
